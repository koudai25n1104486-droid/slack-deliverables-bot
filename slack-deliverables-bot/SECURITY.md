# メンションで投稿曜日・時刻を変更する（v0.6.1）

## 使い方

指定した収集元チャンネルに投稿できる人なら、誰でもボットをメンションして指示できます。個人IDの登録や、卒業時のID入れ替えは不要です。

```text
@制作物まとめ 毎週 金曜 18:00
```

ボットは指示のスレッドに「毎週金曜18:00（日本時間）に変更しました」と返答します。

| 指示 | 動作 |
|---|---|
| `@ボット 毎週 金曜 18:00` | 曜日と時刻を変更 |
| `@ボット 毎週金曜日18時に投稿して` | 同じ変更。全角の数字も使用可 |
| `@ボット 投稿曜日 金曜` | 曜日だけ変更 |
| `@ボット 投稿時刻 18:30` | 時刻だけ変更 |
| `@ボット 設定確認` | 現在の設定と週次実行の有効／無効を確認 |
| `@ボット ヘルプ` | 使い方を表示 |
| `@ボット 今週の制作物` | 今週月曜から現在までを随時集計。詳細は [REPORT.md](REPORT.md) |

時刻は日本時間です。24時間表記の00:00〜23:59を指定します。
AIによる自由な指示解釈ではなく、上記の定型文を解析します。「今すぐ投稿」等、表にない指示を実行する機能はありません。

## 1. Slack側の追加設定

アプリ管理画面（https://api.slack.com/apps）で、使用しているアプリを開きます。

1. **OAuth & Permissions → Bot Token Scopes** に **`app_mentions:read`** を追加します。
2. **Event Subscriptions → Enable Events** をオンにします。
3. **Subscribe to bot events → Add Bot User Event** で **`app_mention`** を追加し、保存します。
4. **OAuth & Permissions** からワークスペースに再インストールします。
5. Socket Modeをオンにしたままにします。公開Request URLは不要です。

`commands`、ショートカット、`message.channels` のリアルタイム購読は不要です。週次の制作物抽出は引き続き履歴取得で行います。
更新した `slack-manifest.json` にも追加権限と `app_mention` 購読を含めています。

## 2. 操作できる人

指定チャンネルに投稿できる参加者全員が、曜日・時刻の変更と設定確認を行えます。
学校の運用担当者が最初に対象チャンネルと機能の有効化を設定しますが、利用者ごとのID登録は行いません。
チャンネル外からの指示は受け付けず、ボット自身や他のボットからの指示も無視します。

## 3. コードと.envを更新

ボットを停止し、今回のコード一式へ更新します。既存の `.env` と `.state` を引き継いでください。

```bash
npm ci --ignore-scripts
```

`.env` に次を設定します。個人のメンバーIDは不要です。

```dotenv
ENABLE_MENTION_COMMANDS=true
ALLOW_SLACK_POST=true
```

以前の.envに `SLACK_ADMIN_USER_IDS` が残っていても、この版では参照しません。

## 4. 自動投稿せず練習する

次の設定で、メンションへの返答と予定の変更だけを試せます。

```dotenv
ENABLE_WEEKLY=false
ENABLE_MENTION_COMMANDS=true
ALLOW_SLACK_POST=true
```

```bash
npm start
```

指定の収集元チャンネルで `@ボット 毎週 金曜 18:00` と投稿してください。
ボットが返答し、その後 `@ボット 設定確認` で設定を確認できれば成功です。
この段階では週次まとめとCanvas追記は自動実行されません。

## 5. 本番の週次実行

設定できたら停止し、`ENABLE_WEEKLY=true` に変更して `npm start` します。
メンションで設定した予定は保存済みなので、再起動しても維持されます。
既存の `OUTPUT_MODE=both`、チャンネルID・Canvas ID等は引き続き使います。

## 適用ルール

- 初期設定は毎週月曜9:00、日本時間です。
- 変更した予定は、指示後に到来する次の予定から適用します。過去の曜日へ変更した直後に遡って投稿しません。
- 同じ設定の再指定では次回適用時刻を先延ばししません。
- **変わるのは投稿する曜日・時刻だけです。集計対象は引き続き「前週の月曜0時〜今週の月曜0時」です。** 金曜に設定しても金曜直前7日分へは切り替わりません。
- 同じ週のまとめが既に処理済みなら、曜日を変えても再投稿・再追記しません。次の未処理週から反映します。
- 実行中のまとめは中断しません。新しい設定は以後の未処理分に適用します。
- 指定した収集元以外のチャンネル・ボット・利用者不明・10分を超えて古い指示は応答せず無視します。
- `ALLOW_SLACK_POST=false` の場合、メンション操作や返答も無効です。
- メンションで週次実行そのものを有効化する機能はありません。`ENABLE_WEEKLY` は稼働環境の管理者が.envで設定します。
- Node.js標準タイマーで1分ごとに予定を確認します。処理中・API障害等で遅れる場合があります。
- 稼働環境が停止・スリープ中は操作も自動実行もできません。週をまたいで停止した分の自動補完は行いません。
- `npm run post:test`、`npm run post:weekly` は手動実行なので、設定曜日を待たずに実行します。

## 保存情報と復旧

`.state/schedule.json` に曜日・時刻・適用開始時刻と、重複配信を抑止する直近100件のイベント識別子を保存します。指示本文や操作した利用者IDはここに保存しません。
管理者IDの許可リストは使いません。参加者のプロフィール等を追加取得する処理はありません。

Slackが同じイベントを再配信しても、二重に設定・返答しないようにしています。設定保存後に返答だけが通信エラーとなる場合もあるため、返答が来ないときは `設定確認` で確認してください。

保存ファイルが壊れている場合は、既定の月曜9時へ黙って戻さず、処理を停止します。
設定を初期化する場合は、ボットを停止して担当者が `schedule.json` を確認してください。このファイルを削除すると初期の月曜9時に戻ります。実行記録の `ledger.json` は削除しないでください。
強制終了で `schedule.lock` が残った場合は、稼働プロセスがないことを確認してから担当者が削除します。

## 学校への追加説明

> 指定チャンネルに投稿できる参加者全員が、ボットをメンションして投稿曜日・時刻の変更と設定確認を行える機能です。卒業時等の個人IDの入れ替えは不要です。app_mentions:read権限とapp_mentionイベントを使用します。指示は定型文で解析し、外部AIや外部サイトへ送信しません。
> 個人IDの許可リストは使用せず、曜日・時刻等と重複防止用イベント識別子だけをローカル保存します。指示本文や操作利用者IDをログ・予定ファイルへ保存しません。プロフィール取得は行いません。

## 随時集計も利用できます

v0.7.0から、同じメンション機能で `今週の制作物`、`報告` 等を受け付けます。集計対象は今週月曜からその時点までで、週次報告の前週分とは異なります。予定・週次の実行記録・Canvasは変更しません。詳細は [REPORT.md](REPORT.md) を参照してください。

## 好きな時に最新分を見る

`@ボット 今週の制作物` と指示すると、今週月曜から現在までを指示のスレッドに表示します。これは閲覧用の随時集計で、Canvasや週次報告には追加しません。詳しくは [REPORT.md](REPORT.md) を参照してください。

## 随時集計（v0.7.0）

- 指定チャンネルの参加者からのメンションで、今週月曜0時〜集計開始時点の履歴を追加取得し、分類別の元投稿リンクを指示のスレッドへ返します。
- 使用するAPIと権限は既存の履歴取得・元投稿リンク取得・メッセージ投稿です。外部AI・外部URLアクセス・ファイル実体のダウンロードは追加しません。
- 結果本文・ファイル名・画像本体はメモリで扱い、サーバーへ永続保存しません。既存のメンション処理でイベント識別子を重複防止のため記録します。
- 週次の実行記録・予定設定・Canvas・ピンは変更しません。同じプロセス内で週次の処理と順番に実行し、随時集計の履歴取得は開始から30秒間隔に制限します。
- 表示途中の通信失敗時は内容を自動再送せず、利用者へ部分表示の可能性を案内します。
