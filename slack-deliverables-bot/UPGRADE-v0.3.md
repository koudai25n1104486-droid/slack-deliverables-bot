# タグで分類する版への更新（v0.3.1）

## 投稿する人の操作

同じチャンネルの投稿本文に、次のように記載して画像等を添付するだけです。

```text
#制作物-イラスト
新しい作品です。
```

半角の `#` と `-` を使い、タグを単独の行にしてください。

| タグ | 見出し |
|---|---|
| `#制作物-イラスト` | イラスト |
| `#制作物-動画` | 動画 |
| `#制作物-文章` | 文章 |
| `#制作物-音楽` | 音楽 |
| `#制作物-その他` | その他 |
| `#制作物` | 制作物 |
| `#制作物-候補にない名前` | 制作物 |

複数のタグを書いた場合は、先頭の対象タグの分類になります。分類は同じ投稿内の添付全体に適用します。

## 管理担当者の更新操作

1. 起動中のボットをControl＋Cで停止します。
2. 更新版の `src/`、`package.json`、`package-lock.json`、`categories.json` と文書を配置します。既存の `.env` と `.state/ledger.json` は引き継いでください。
3. コードのフォルダで `npm ci --ignore-scripts` を実行します。
4. `npm run mock` で架空の表示を確認します。
5. テスト用の投稿を先に行い、`npm run preview` を実行します。結果の `categories` に、見出しごとの件数が表示されます。Slackへの投稿は行いません。
6. 週次運用を再開する場合は、従来どおり `ALLOW_SLACK_POST=true` と `ENABLE_WEEKLY=true` で `npm start` します。

本文タグのために追加するSlack権限や設定はありません。既存のトークンとチャンネルIDを使えます。`ENABLE_CATEGORIES` はこの版では参照しないため、以前の `.env` に残っていても影響しません。

## 旧版のメニューを作成済みの場合

旧ショートカット「制作物の分類」はこの版では使いません。分類に使っていた `commands` 権限も要求しません。学校の管理担当者が不要なショートカット・権限を整理してください。発行済みトークンに古い権限が残る可能性がある点はREADMEの説明を参照してください。

旧版の `.state/categories.json` に保存した分類は参照しません。過去の投稿にも分類を付けたい場合は、本文を `#制作物-イラスト` 等に編集してください。既に投稿したまとめは自動更新しません。

## 繰り返しテストするとき

同じ日の `post:test` が実行済みだと、重複防止で `already_processed` になります。分類の読み取りだけなら `preview` は何度でも使えます。追加テストは `npm run post:test -- --run-id=2` を実行します。次は3、4と番号を変えてください。過去のまとめや実行記録は残ります。同じ番号を再実行すると二重投稿を防ぎます。番号は1〜9999で、週次実行には指定できません。

## 分類候補の変更

コード直下の `categories.json` を編集し、常駐中のボットを再起動します。

```json
["イラスト", "動画", "文章", "音楽", "その他"]
```

候補にない値や分類の誤字は「制作物」になります。候補の名前に空白・改行・タグの区切り記号は使えません。新しい外部保存先や分類データベースはありません。
